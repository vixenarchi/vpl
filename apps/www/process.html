how a person gets from here to using it

Process

  1. 1

    Put something real into a tool

    Half an hour tells you whether this way of working suits you. Not a demo, not a sample project — the note you would have written anyway, the requirement you would have argued about anyway, the receipt you have to file anyway.

  2. 2

    Read the code, or bring the problem

    Everything is at github.com/vixenarchi/vpl: every application and the whole shell, Apache-2.0. You can read it, run it, fork it, and change it without asking. If reading is not what you want to do, bring the problem and have it answered.

  3. 3

    Keep it, and let it evolve

    Things are added; nothing is rewritten to make room. The next layer arrives when the work needs it, not when a roadmap says so. Nothing is installed, so leaving is also one page: your data is yours, in a database in the EU, exportable at any time.

No call, no onboarding, no six-week discovery. The first step is a tool, and it is open in a tab.
